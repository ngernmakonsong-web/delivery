# ระบบจัดส่งสินค้า — คู่มือระบบการทำงาน

เอกสารนี้อธิบายว่าระบบทำงานอย่างไร ใครทำอะไรได้บ้าง และข้อมูลเก็บที่ไหน
เขียนไว้เพื่อให้คนที่มาดูแลต่อ หรือผู้ช่วย AI ในแชตใหม่ อ่านแล้วเข้าใจได้ทันที
โดยไม่ต้องย้อนไปอ่านบทสนทนาเดิม

- **เว็บใช้งาน** https://ngernmakonsong-web.github.io/delivery/
- **โค้ด** https://github.com/ngernmakonsong-web/delivery
- **ฐานข้อมูล** Supabase โปรเจกต์ `wopgcutgbfojkklayiqg` (แผนฟรี)

## 1. ภาพรวม

เว็บแอปสำหรับทีมจัดส่งสินค้า ใช้บนมือถือเป็นหลัก รองรับงาน 3 ประเภท
คือ **ส่งสินค้า วางบิล และรับเช็ค** มีการติดตามตำแหน่งรถ คำนวณเส้นทางจริงบนถนน
บังคับถ่ายรูปก่อนปิดงาน และมีขั้นตรวจงานโดยหัวหน้า

ข้อมูลทั้งหมดอยู่บนเซิร์ฟเวอร์กลาง ทุกเครื่องเห็นข้อมูลชุดเดียวกันแบบสด
คนขับเปลี่ยนมือถือแล้วล็อกอินใหม่ได้ข้อมูลครบเหมือนเดิม

## 3. วงจรชีวิตของงาน

```
รอจัดงาน (pending)
    ↓ หัวหน้ามอบหมาย
มอบหมายแล้ว (assigned)
    ↓ คนขับกด "เริ่มเดินทาง"            ขั้น 1/4
กำลังเดินทาง (enroute)
    ↓ คนขับกด "ถึงร้านแล้ว"             ขั้น 2/4
ถึงร้าน (arrived)
    ↓ คนขับถ่ายรูป (บังคับ)             ขั้น 3/4
    ↓ คนขับปิดงาน                        ขั้น 4/4
ปิดงานสำเร็จ (done) หรือ ปิดงานไม่สำเร็จ (failed)
    ↓ เข้าคิวรอตรวจอัตโนมัติ
รอตรวจ (review pending)
    ├─ หัวหน้ากด "ผ่าน"    → จบงาน
    └─ หัวหน้ากด "ส่งกลับแก้" → กลับไปสถานะ "ถึงร้าน" ให้คนขับแก้แล้วปิดใหม่
```

**กฎที่บังคับไว้**

- ปิดงานได้เฉพาะเมื่อสถานะเป็น "ถึงร้าน" แล้วเท่านั้น ข้ามขั้นไม่ได้
- **ต้องมีรูปอย่างน้อย 1 รูปก่อนปิดงาน** ทั้งกรณีสำเร็จและไม่สำเร็จ
  ถ้ายังไม่มีรูป ปุ่มปิดงานจะไม่ขึ้นมาเลย
- ออฟฟิศข้ามขั้นถ่ายรูปได้ในกรณีจำเป็น (กล้องเสีย เน็ตล่ม)
  แต่ระบบบันทึกไว้ที่ `closed_without_photo` และติดป้ายแดง "ไม่มีรูป"
- ปิดงานไม่สำเร็จ **ต้องระบุสาเหตุ** และเลือกวันนัดใหม่ได้
  ถ้าเลือกวันนัดใหม่ ระบบสร้างงานรอบถัดไปให้อัตโนมัติ ผูกกับงานเดิมผ่าน
  `parent_job_id` / `child_job_id` และเพิ่ม `round` ขึ้นทีละ 1
- **ทุกงานที่ปิดแล้วต้องมีคนกดตรวจผ่าน** ไม่มีงานไหนผ่านเอง
  แม้หัวหน้าจะเป็นคนปิดงานเองก็ต้องมีคนกดตรวจ
- งานที่ปิดแล้ว คนขับเปิดดูและแก้ไขไม่ได้ ตรวจได้เฉพาะออฟฟิศและผู้ดูแล

**บันทึกพิกัดทุกครั้งที่เปลี่ยนสถานะ** เก็บใน `events` เป็นอาร์เรย์
แต่ละรายการมี `{st, at, lat, lng, acc}` ย้อนดูได้ว่าไปถึงร้านไหนเวลาเท่าไร

## 4. ประเภทงานและข้อมูลที่เก็บ

### ส่งสินค้า (deliver)
- เลขที่บิล / ใบส่งของ, ยอดบิล
- รายการสินค้า (ชื่อ จำนวน หน่วย) หลายรายการ
- เก็บเงินปลายทาง: ยอดที่ต้องเก็บ, ยอดที่รับจริง, รับเป็นเงินสดหรือโอน
  ถ้ารับไม่ตรงยอด ระบบแสดงส่วนต่างให้เห็น

### วางบิล (bill)
- เลขที่ใบวางบิล, บิลที่วาง (หลายเลขได้), ยอดรวม
- วันนัดรับเช็ค — ใส่ไว้แล้วตอนปิดงานจะมีปุ่ม
  **สร้างงานรับเช็คต่อในวันนั้นอัตโนมัติ** พร้อมสืบยอดและเลขบิลมาให้

### รับเช็ค (cheque)
- รับชำระเป็น เช็ค / เงินสด / โอน สลับได้หน้างาน
  ตั้งไว้เป็นเช็คก่อนได้ ถ้าลูกค้าจ่ายสดค่อยกดเปลี่ยนตอนปิดงาน
- ถ้าเป็นเช็ค: เลขที่เช็ค, ธนาคาร, วันที่ลงเช็ค
- ยอดเงิน, บิลที่ตัด

## 5. ร้านค้า

- รหัสร้าน, ชื่อ, ที่อยู่, ผู้ติดต่อ, เบอร์โทร, หมายเหตุ
- **เวลารับของ** เลือกเป็นเวลา ตั้งแต่กี่โมงถึงกี่โมง (ไม่ใช่พิมพ์)
- **รอบวางบิล** กดเลือกจากตารางวันที่ 1-31 และสิ้นเดือน
  หรือเลือกเป็นวันในสัปดาห์ พร้อมช่องหมายเหตุแยก
- **พิกัด (หมุด)** ปักได้ 3 วิธี
  1. เลือกจุดบนแผนที่ (แม่นที่สุด เปิดเป็นภาพดาวเทียมให้เห็นตัวอาคาร)
  2. ใช้ตำแหน่งปัจจุบัน (รอสัญญาณ 8 วินาทีเพื่อความแม่น เตือนถ้าคลาดเกิน 50 ม.)
  3. วางพิกัดที่คัดลอกจาก Google Maps

**คีย์รหัสลูกค้าแล้วดึงประวัติ** ในฟอร์มสร้างงาน พิมพ์รหัสแล้วกดค้นหา
ระบบจะเลือกร้านให้พร้อมแสดงที่อยู่ เบอร์ เวลารับของ รอบวางบิล สถานะหมุด
และประวัติงาน 3 ครั้งล่าสุด มีปุ่มดึงรายการสินค้าและยอดเงินจากงานก่อนหน้ามาใช้ซ้ำ

## 6. เส้นทางและแผนที่

ใช้ **OSRM** (`router.project-osrm.org`) บริการเปิดฟรี ไม่ต้องใช้คีย์
คำนวณจากถนนจริง ไม่ใช่ระยะเส้นตรง

- การ์ดงานทุกใบบอกระยะและเวลาขับจากจุดก่อนหน้า
- กล่องสรุปบอกร้านถัดไป ระยะ เวลา เวลาที่จะไปถึง และยอดรวมทั้งวัน
- แผนที่วาดเส้นทางจริงตามถนน พร้อมป้ายเวลาติดถาวรข้างหมุดแต่ละร้าน
- **ปิดงานแล้วเด้งหน้าร้านถัดไปทันที คิดจากตำแหน่งที่ยืนอยู่จริงตอนนั้น**
- จัดลำดับแนะนำใช้ OSRM trip หาลำดับที่สั้นที่สุด คนขับปรับเองได้ตลอด
- คนขับแต่ละคนมีสีประจำตัว ใช้ทั้งเส้นทาง หมุด จุดรถ และรายชื่อ
  ออฟฟิศเลือก "ทั้งหมด" เห็นทุกคันพร้อมกัน แต่ละคันคิดจากตำแหน่งของคันนั้นเอง
- สลับแผนที่ถนน / ภาพดาวเทียมได้ หน้าปักหมุดเปิดเป็นดาวเทียมเสมอ

**เก็บผลไว้ 14 วัน** ใน localStorage ลดการเรียกซ้ำ และหน่วงไม่ให้ยิงถี่เกิน
ถ้าเรียกไม่ได้ จะถอยไปใช้ค่าประมาณ (เส้นตรง × 1.35 ที่ 28 กม./ชม.)
แล้วบอกผู้ใช้ว่าเป็นค่าประมาณ แอปไม่พัง

**ยังไม่รวมรถติด** เพราะข้อมูลจราจรสดต้องเสียเงินทุกเจ้า

## 7. การย้ายงาน

- **หัวหน้า/ผู้ดูแล** ย้ายได้ทันที เลือกคนขับและวันที่
- **คนขับ** ย้ายเองไม่ได้ กดได้แค่ "ขอย้ายงาน" งานยังเป็นของตัวเองจนกว่าจะอนุมัติ
- **อนุมัติได้ 2 ทาง** คนขับที่รับงานกด "รับงาน" เอง หรือหัวหน้ากด "อนุมัติ"
- ปฏิเสธได้พร้อมเหตุผล ผู้ขอยกเลิกคำขอเองได้
- งานหนึ่งมีคำขอค้างได้ครั้งละรายการเดียว (unique index `jt_one_pending`)
- ป้ายสีส้มบนแถบด้านบนบอกจำนวนคำขอที่รอเราตัดสินใจ

## 8. ความปลอดภัย

ใช้ **Row Level Security ของ Postgres** บังคับทุกอย่างที่ฐานข้อมูล

- `jobs_select` — คนขับได้เฉพาะแถวที่ `driver_id = auth.uid()` ออฟฟิศได้ทุกแถว
- `jobs_update` — เงื่อนไขเดียวกัน และ `with check` กันไม่ให้โยนงานให้คนอื่น
- `jobs_delete` — เฉพาะออฟฟิศ
- `profiles_delete` — เฉพาะผู้ดูแล และลบบัญชีตัวเองไม่ได้
- ทริกเกอร์ `profiles_guard` — กันคนขับเลื่อนขั้นตัวเองเป็นออฟฟิศ
- ทริกเกอร์ `jobs_guard_closed` — ปฏิเสธการแก้งานที่ปิดแล้ว ถ้าคนสั่งไม่ใช่ออฟฟิศ
- ฟังก์ชัน `approve_transfer` / `reject_transfer` เป็น security definer
  เพราะคนอนุมัติยังไม่ใช่เจ้าของงาน จึงแก้ตรง ๆ ไม่ได้ ฟังก์ชันตรวจสิทธิ์เองก่อนทำ

**คีย์ที่ฝังในหน้าเว็บ** (`js/config.js`) เป็น publishable key ซึ่งออกแบบมาให้เปิดเผยได้
ความปลอดภัยมาจากกฎสิทธิ์ ไม่ใช่การซ่อนคีย์
**ห้ามใส่คีย์ `sb_secret_...` ลงในโค้ดเด็ดขาด** คีย์นั้นข้ามกฎสิทธิ์ได้ทั้งหมด

**ยังไม่ได้ทดสอบเจาะ** การทดสอบว่าคนขับยิงคำสั่งตรงแล้วถูกปฏิเสธจริงไหม
ยังทำไม่ครบ เพราะต้องเขียนข้อมูลลงฐานข้อมูลจริง ควรทดสอบก่อนใช้งานเต็มรูปแบบ

## 9. โครงสร้างข้อมูล

| ตาราง | ใช้ทำอะไร |
|---|---|
| `profiles` | ผู้ใช้และบทบาท ผูกกับ `auth.users` ด้วย id เดียวกัน |
| `stores` | ร้านค้า พิกัด เวลารับของ รอบวางบิล |
| `jobs` | งานทั้งหมด ทุกประเภท ทุกสถานะ |
| `job_transfers` | คำขอย้ายงานที่รออนุมัติ |
| `driver_positions` | ตำแหน่งล่าสุดของคนขับแต่ละคน |
| storage bucket `photos` | รูปถ่ายหน้างาน |

**ชื่อฟิลด์** ฐานข้อมูลใช้ snake_case แอปใช้ camelCase
แปลงกันที่ `js/cloud.js` ฟังก์ชัน `jobIn`/`jobOut`/`storeIn`/`storeOut`
**เพิ่มฟิลด์ใหม่ต้องแก้ทั้งสองฝั่ง** ไม่งั้นค่าจะหายตอนบันทึก

**username กับอีเมล** ระบบยืนยันตัวตนของ Supabase ใช้อีเมล
แอปจึงแปลง `username` เป็น `username@delivery.local` ภายใน
ผู้ใช้เห็นแค่ username ตั้งแล้วเปลี่ยนไม่ได้

## 10. ไฟล์ในโปรเจกต์

```
index.html              โครงหน้าจอ และลำดับการโหลดสคริปต์
css/app.css             สไตล์ทั้งหมด
js/config.js            ค่าเชื่อมต่อ Supabase (ถ้าเว้นว่าง = โหมดเก็บในเครื่อง ไม่มีล็อกอิน)
js/db.js                เก็บข้อมูลในเครื่อง (IndexedDB) ใช้ตอนยังไม่ต่อเซิร์ฟเวอร์
js/cloud.js             ตัวเชื่อม Supabase เปิดเมธอดชุดเดียวกับ db.js
js/core.js              ค่าคงที่ สถานะแอป GPS สิทธิ์ แผนเส้นทาง ตัวควบคุมหน้าจอ
js/auth.js              หน้าล็อกอิน จัดการบัญชี ย้ายข้อมูลขึ้นคลาวด์
js/views.js             หน้าจอทุกหน้า และรายละเอียดงาน
js/forms.js             ฟอร์มทั้งหมด ปิดงาน ตรวจงาน ย้ายงาน รูปถ่าย ส่งออก CSV
js/route.js             คำนวณเส้นทางจริงบนถนน (OSRM) พร้อมแคชและค่าสำรอง
js/map.js               แผนที่ Leaflet เส้นทาง หมุด ป้ายเวลา
sw.js                   service worker ติดตั้งเป็นแอปและอัปเดตอัตโนมัติ
supabase-setup.sql      สร้างฐานข้อมูลทั้งหมดตั้งแต่ต้น
supabase-update.sql     ส่วนที่เพิ่มทีหลัง รันต่อจากของเดิมได้ รันซ้ำได้
```

**หลักการที่ยึดไว้** `js/cloud.js` เปิดเมธอดหน้าตาเหมือน `js/db.js`
หน้าจอจึงเรียก `DB.jobs.put()` เหมือนกันไม่ว่าเก็บที่ไหน
ตอนบูต `js/core.js` เลือกว่าจะชี้ `window.DB` ไปที่ `LocalDB` หรือ `Cloud`

**ต้องเพิ่มเลขเวอร์ชันใน `sw.js`** (`const CACHE = 'delivery-vNN'`) ทุกครั้ง
ไม่งั้นเครื่องผู้ใช้จะยังได้โค้ดเก่า

**แก้ฐานข้อมูล** เขียนเพิ่มใน `supabase-update.sql` แล้วให้ผู้ดูแลรันที่ SQL Editor
เขียนให้รันซ้ำได้เสมอ (`if not exists`, `create or replace`, `drop ... if exists`)
**ห่อคำสั่งที่อาจพลาดด้วย `exception when others`** เพราะ Postgres รันทั้งไฟล์
เป็นธุรกรรมเดียว พลาดจุดเดียวจะย้อนกลับทั้งหมด (เคยเกิดมาแล้ว ตารางไม่ถูกสร้างเลย)

**แคชของ Supabase** หลังสร้างตารางใหม่ PostgREST อาจยังไม่เห็น ขึ้น `PGRST205`
แก้ด้วย `notify pgrst, 'reload schema';` แอปมีตัวลองซ้ำ 8 ครั้งรองรับอยู่แล้ว
ถ้าเจอ `42P01` จาก SQL Editor แปลว่าตารางไม่มีจริง ไม่ใช่เรื่องแคช

**สร้างบัญชีคนขับ** ผู้ดูแลเท่านั้น ที่ไอคอนมุมขวาบน → บัญชีผู้ใช้ → สร้างบัญชีใหม่
ระบบสุ่มรหัสผ่านให้ จดก่อนปิดหน้า เพราะไม่แสดงอีก
**ตั้งรหัสผ่านใหม่ให้คนอื่นทำจากในแอปไม่ได้** ต้องไปที่
Supabase → Authentication → Users → Reset password

## 12. ข้อจำกัดที่ควรรู้

- **GPS ส่งได้เฉพาะตอนเปิดแอปค้างบนหน้าจอ** สลับแอปหรือจอดับจะหยุดส่ง
  เป็นข้อจำกัดของเบราว์เซอร์ทุกยี่ห้อ ระบบจึงบันทึกพิกัดทุกครั้งที่เปลี่ยนสถานะแทน
  ถ้าต้องการติดตามต่อเนื่อง ตั้งมือถือที่แท่นหน้ารถ เสียบชาร์จ เปิด "กันจอดับ"
- **โปรเจกต์ Supabase แผนฟรีจะหยุดชั่วคราวถ้าไม่มีใครใช้ 7 วัน** ใช้ทุกวันไม่มีปัญหา
- **OSRM เป็นบริการฟรีของชุมชน ไม่รับประกันว่าจะไม่ล่ม** ถ้าใช้หนักจนโดนจำกัด
  เปลี่ยนไปใช้ OpenRouteService ได้ (ฟรี 2,000 ครั้ง/วัน ต้องสมัครคีย์)
- **ยังไม่รองรับการใช้งานตอนออฟไลน์** ต้องมีเน็ตตลอด
- **รูปถ่ายเก็บใน Supabase Storage แผนฟรีได้ 1 GB** รูปถูกย่อเหลือกว้าง 1280px
  คุณภาพ 72% ประมาณ 100 KB ต่อรูป ใช้ได้ราว 10,000 รูป
  ถ้าใกล้เต็มต้องวางแผนลบรูปเก่าหรืออัปเกรด
- **ยังไม่มีระบบแจ้งเตือนเข้ามือถือ** ต้องเปิดแอปดูเอง
